# الأفق الأول — سجل القرارات المنفذة (2026-10)

## ما بُني (مقبوض بالدليل لا بالوصف)
- **التجديد التلقائي Phase 1**: آلة حالات (active→due_soon→grace→suspended) + كرون يومي + reset ذري عند الدفع + **إنفاذ قراءة فقط** (402 للكتابة) + بانر. القرار: القراءة فقط لا الحجب (ثقة > إكراه).
- **خصم التجديد المبكر 5%**: شهري فقط، سيرفر-سايد، كل دورة (لا مرة واحدة) + عرض السعر قبل Paymob.
- **إيصالات فورية**: مالك + ولي أمر، dedupe بمعرف العملية، القناة واتساب→SMS.
- **تدقيق الغياب الصامت**: كرون يرصد الحصص بلا تسجيل → ينبه المالك فقط (لا كتابة `absent` تلقائية أبداً).
- **تقارير الأهالي**: توليد + push، وعند الفشل واتساب/SMS تلقائياً (بعد إثبات صفر مشتركي push).
- **بنية الكرون**: بوابة تردد fail-closed + UTC موثق + `?secret=` + إصلاح `*/15` المرفوض صامتاً + تدوير السر + فحص حي مجدول + مونيتورا UptimeRobot.
- **الأمان**: تنقية PII قبل Sentry + تنقية URLs موسعة (اعتمادات سنة كاملة) + RLS مكتمل + توثيق عزل صادق.

## قرارات مبدئية ثبتت
1. الضغط على الدافع فقط — الطلاب/الأهالي خارج أي إنفاذ.
2. لا ثقة بحالة معلنة بلا استدعاء حي (سجل `ops-external.md` المركزي).
3. الفشل المغلق دائماً (بوابات exit 1، لا أخضر كاذب، لا skip صامت).
4. التصميم قبل الكود للميزات، والتحقق المستقل قبل القبول دائماً.

## المفتوح (بيد المالك حصراً)
- قبول Paymob (قيد المراجعة) → مفاتيح حية → دفع تجريبي.
- سجل تجاري → WhatsApp رسمي (القنوات البديلة تعمل اليوم).
- مونيتورا UptimeRobot بالقيمة المدورة (أُنشئا ويعملان).
- خطة Supabase المدفوعة → تدريب PITR (الـrunbook جاهز).

## تصحيح موثق: تفعيل واتساب ليس "تبديل مفتاح" (2026-10)
- `sendWhatsAppText` يرسل `type:"text"` فقط (نافذة 24 ساعة) — لا مسار `template` (HSM) للرسائل المبدوءة من السنتر؛ يُبنى قبل التفعيل لا بعده.
- `POST /api/whatsapp/webhook` إقرار 200 فقط — بلا تتبع تسليم ولا التقاط ردود (نافذة الـ24 ساعة تعتمد عليها).
- القرار المنفذ: **تفضيل صريح** — نجاح واتساب يُسكت Telegram لنفس الحدث (لا ازدواج)؛ Telegram بديل عند الفشل فقط.
- جدول `message_templates` للتخصيص النصي الحر — ليس قوالب Meta المعتمدة (UTILITY/HSM تُعتمد لاحقاً).
